## 1. 프로젝트 개요 (Overview)

### 1.1 배경 및 목적
직업계 고등학교 도제교육(일학습병행제)은 교내 이론 및 실습 교육(**off-JT**), 기업 현장 실무 훈련(**OJT**), 일반 학사일정, 방과후/특별수업, 국가공휴일 및 국가공인 역량평가/자격시험 마일스톤이 복합적으로 교차되어 운영됩니다.  
이로 인해 학생, 학부모, 기업 현장교사, 학교 도제부 교직원 모두가 일정을 명확하게 파악하고 이수 시간을 관리하는 데 큰 어려움을 겪고 있었습니다.

본 시스템은 **Google Spreadsheet**를 간편한 클라우드 DB로 채택하고, **Google Apps Script(GAS)**를 고신뢰성 서버리스 API 백엔드로 활용하며, 브라우저에서 즉시 구동되는 **Single-File 반응형 웹 캘린더**를 구축하여 다음 목적을 달성합니다:
1. **일정 시각화 극대화**: 월간/1주간/2주간 뷰와 카테고리별 컬러 코딩 및 다중 필터링 지원
2. **이수 시간 자동 집계**: 화면에 표시된 일정 기준 off-JT / OJT 일수 및 시간 실시간 계산
3. **보안 인증 기반 실시간 운영**: 비밀번호 기반 세션 인증을 통한 공지사항, 디데이, 일정 추가/수정/삭제
4. **프리미엄 사용자 경험(UX)**: 브라우저 기본 팝업을 탈피한 자체 모달/토스트 시스템 탑재 및 일정표 고해상도 캡처 다운로드 제공

## 3. 핵심 제품 요구사항 (Functional Requirements)

### 3.1 캘린더 시각화 및 내비게이션
- **FR-101 (월간 뷰 / Month View)**: 해당 연·월을 7열(일~토) 그리드로 출력하며 이전/다음 달 연결 날짜를 투명도와 함께 배치.
- **FR-102 (주간 뷰 / Week View)**: 선택 기준일 기준 1주간(7일) 또는 2주간(14일) 집중 뷰를 제공하여 연속적인 훈련 흐름 파악.
- **FR-103 (기간 이동 및 오늘 복귀)**: 이전(`‹`), 다음(`›`) 버튼을 통한 월/주 단위 날짜 전환. **뷰(월간/1주간/2주간)를 전환해도 보고 있던 기간이 유지**되며, `오늘` 버튼으로 언제든 현재 날짜가 포함된 기간(월간은 이번 달, 주간은 이번 주)으로 즉시 복귀합니다.
- **FR-104 (스마트 카테고리 컬러 코딩)**:
  - 🔵 `교내 교육 (off-JT)`: 파란색 (`--blue-offjt: #3979f6`)
  - 🔴 `현장 훈련 (OJT)`: 핀터레스트 레드 (`--red-ojt: #e60023`)
  - 🟢 `특별수업 (방과후)`: 에메랄드 그린 (`--green-special: #107c41`)
  - 🟣 `특별수업 (기타 특강/캠프)`: 핀터레스트 퍼플 (`--purple-special: #7e238b`)
  - 🌸 `휴업일 / 공휴일`: 연분홍/적색 테두리 배지
  - ⚫ `학사일정 / 일반`: 슬레이트 (`--gray-general: #475569`) — 기존 올리브 계열(`#62625b`)이 off-JT 블루·특별수업 퍼플과 겉돌아, 같은 채도 계열의 차분한 슬레이트로 조정. 가장 빈번한 분류이므로 다른 색을 누르지 않도록 의도적으로 낮은 채도를 유지합니다.
- **FR-105 (다중 선택 필터링 / Multi-Select Filter)**: `전체 일정 보기` 복귀 칩 및 `학사일정`, `off-JT`, `OJT`, `특별수업` 등 여러 카테고리를 동시에 2개 이상 선택하여 중복 필터링 조회 지원.
- **FR-106 (캘린더 내부 11px 정밀 타이포그래피)**: 날짜 셀(`.calendar-cell`), 날짜 숫자(`.cell-number`), 일정 배지(`.event-badge`), 요일 헤더(`.day-header`)의 글자 크기를 정밀한 **11px**로 표준화하여, 일정 텍스트가 좁은 칸 안에서도 잘림 없이 가독성 높게 표시되도록 최적화.

### 3.2 통계 대시보드 및 지표 산출
- **FR-201 (off-JT 집계)**: 현재 달력 화면에 렌더링된 일정을 기준으로 고유 훈련 일수(Set 집계) 및 총 이수시간 합산. 일정명에 `Off-JT(2)` 또는 뒤에 추가 문구가 붙은 경우에도 정밀 정규식 엔진(`/\((\d+)\)/`)을 통해 정확한 시간 추출(기본 7시간 또는 파싱된 N시간).
- **FR-202 (OJT 집계)**: 현재 달력 화면에 렌더링된 일정을 기준으로 고유 훈련 일수(Set 집계) 및 총 이수시간 합산. `OJT(5) 제4과목평가`와 같이 괄호 뒤에 부가 설명이 붙어 있어도 기본값(8시간)으로 잘못 치환되지 않고 정확하게 괄호 안의 시간(`5시간`)을 추출하여 오차 없는 정확한 통계 보장.
- **FR-203 (방과후 수업 집계)**: 현재 달력 화면에 렌더링된 방과후 수업 일정을 기준으로 고유 일수(Set 집계) 및 총 이수시간 합산 (기본 2시간 또는 정밀 파싱된 N시간, 에메랄드 그린 테마).
- **FR-204 (차기 마일스톤 D-Day)**: 등록된 마일스톤 중 오늘 이후 가장 가까운 일정의 남은 일수(`D-Day`, `D-N`) 및 명칭 실시간 산출.
- **FR-206 (누적 이수시간 집계 / 학기·연간)**: 대시보드 상단의 `집계 범위` 토글로 **이번 화면 · 1학기 · 2학기 · 연간** 중 선택하여 누적 이수시간을 조회합니다.
  - **학기 구분은 `설정` 시트의 날짜를 따릅니다.** 학기 경계는 학교마다 다르고 월 단위로 떨어지지도 않습니다(예: `8/13 방학 · 8/14 개학`). 코드에 규칙을 박으면 8월처럼 한 달 안에 두 학기가 섞인 경우 이수시간이 통째로 잘못 잡히므로, 학사일정을 시트에 직접 적고 **날짜 단위로 집계**합니다.
  - **미등록 시 폴백**: 시트에 학기 날짜가 없으면 월 단위 기본 구분(`1학기 = 3~8월`, `2학기 = 9월~익년 2월`)으로 동작하며, 캡션에 `· 기본 구분`이 표시되어 어떤 기준인지 드러납니다.
  - **집계 구간 표시**: 캡션에 실제 합산 구간을 노출합니다 — `2026학년도 2학기 (8/14 ~ 2/13) 누적`. 기준이 어긋났을 때 화면에서 바로 확인할 수 있습니다.
  - **학년도 기준**: 3월 시작. 기준 학년도는 오늘이 아니라 **현재 조회 중인 기간(`baseDate`)**을 따릅니다. 조회 중인 학년도와 시트에 적힌 학년도가 다르면 기본 구분으로 자동 폴백합니다.
  - **고유 일수 산출**: 날짜 전체(`YYYY-MM-DD`)를 키로 집계하므로 4월 7일과 9월 7일이 각각 1일로 정확히 계산됩니다.
  - **목표 대비 진행률**: `설정` 시트에 연간 목표 이수시간을 등록하면 `연간` 범위에서 카테고리별 진행률 막대와 달성률(`연간 목표 200h 대비 93%`)이 표시됩니다. 목표는 연간 기준값이므로 **학기 범위에서는 막대를 노출하지 않아** 기준이 다른 수치를 비교하는 오해를 막습니다.
  - 선택한 범위는 `localStorage`에 저장되어 다음 방문에도 유지되며, 기본값은 기존 동작과 동일한 `이번 화면`입니다.
- **FR-205 (1024px 쉘 기반 4분할 골든 밸런스 레이아웃)**: 기본 화면 너비를 표준 1024px로 컴팩트하게 수렴하고, 4개 카드(off-JT, OJT, 방과후 수업, D-Day)를 1024px 폭에 최적화된 카드 높이 약 88px(가로 240px 대비 ~2.73:1 황금비율)로 배치하여 한눈에 들어오는 가독성과 캘린더 첫 화면 가시성을 극대화.

### 3.3 일정표 이미지 캡처 & 다운로드
- **FR-301 (무손실 2배율 PNG 내보내기)**: `📸 일정표 저장` 버튼 클릭 시 `html2canvas` 라이브러리를 동적 로드하여 순수 캘린더 영역(`div#calendar-workspace`)을 2배율 선명한 PNG 파일(`성일정보고_달력_{뷰타입}_{기간}.png`)로 생성하여 자동 다운로드. 캡처 시 관리자 패널 및 캡처 버튼은 자동 은닉.

### 3.4 관리자 모드 및 일정 관리
- **FR-401 (보안 인증)**: 서버 환경변수(`Script Properties`)의 비밀번호 대조 후 30분 유효 세션 토큰 발행.
- **FR-402 (D-Day 입력형식 기반 공지 건별 CRUD & 구글시트 행 연동)**: 기존 긴 단일 텍스트 입력 방식에서 탈피하여, D-Day 마일스톤 입력 폼과 완벽히 동일한 **[공지 날짜] (`date`), [공지 내용] (`text`) 2열 분리 입력 폼**을 제공. 구글 스프레드시트의 `공지사항` 시트(`[공지 날짜, 공지 내용, __id]`) 및 `설정` 시트(`Notice`)와 양방향 실시간 동기화되며, 공지 항목 카드는 좁은 폭에서도 글자가 세로로 떨어지지 않도록 **상단 행(공지 내용 100% 가로 확장 + 수정/삭제 버튼)과 하단 행(날짜 뱃지 옆 상태 필 밀착 + 오른쪽 정렬)의 2단 구조**로 단정하게 표시. 현재 날짜 기준 **지난 일정은 맨 뒤 페이지로 자동 이동 정렬(`sortItemsUpcomingFirst`)**되어 다가오는 중요 일정이 1페이지에 우선 노출되며, 4개 단위 페이지네이션, 건별 수정·삭제, 당월 유효 일정 배너 자동 필터링을 지원 (기존 임시 전문 텍스트 편집기 `admin-notice-raw-toggle`는 건별 관리 체계 정착에 따라 제거).
- **FR-403 (D-Day 마일스톤 등록·수정·삭제 풀 CRUD & 지난 일정 맨 뒤 이동)**: 목표 날짜와 명칭을 지정하여 D-Day를 등록하며, 등록된 마일스톤 카드에 **`[수정]` 버튼을 탑재**하여 날짜/명칭 인라인 수정 및 수정 취소 지원. 현재 날짜보다 지난 마일스톤은 **맨 뒤 페이지로 자동 이동 정렬**되어 최신 목표가 1페이지에 바로 보이도록 최적화. 삭제 시 안전 확인 다이얼로그 연동 및 D-Day 실시간 재계산.
- **FR-404 (일정 등록)**: 날짜, 교육 분류, 이수시간(기본값 또는 1~24h), 일정명 입력 후 해당 월 시트에 셀 개행(`\n`) 추가 및 고유 UUID Note 메타데이터 보존.
- **FR-405 (일정 삭제)**: 날짜 셀을 클릭해 열리는 날짜 상세 모달의 일정 목록에서 `🗑️ 삭제` 버튼을 누르면, 안전 확인 모달을 거쳐 시트 셀 값과 Note 메타데이터에서 동시에 제거됩니다.
- **FR-406 (사용자 정의 분류 호환)**: 월별 시트에 기본 6종 외의 분류 열(예: `자격증시험`)을 직접 추가하면 달력·필터 칩은 물론 **등록/수정 폼의 분류 선택 목록에도 자동 반영**됩니다. 백엔드는 기본 분류이거나 이미 시트에 열로 존재하는 분류만 허용하므로, API를 통해 임의의 새 열이 생성되는 것은 계속 차단됩니다.

### 3.5 모던 다이얼로그 & 토스트 시스템
- **FR-501 (커스텀 알림/확인/입력/토스트)**: 브라우저 기본 `alert`, `confirm`, `prompt`를 완전 대체하는 자체 UI 엔진 탑재.

- **FR-503 (보안 비밀번호 모달)**: 관리자 인증 시 비밀번호 마스킹(`••••••••`) 및 눈동자 아이콘 표시/숨김 토글 지원.

## 4. 비기능적 요구사항 (Non-Functional Requirements)

1. **보안성 (Security)**:
   - 관리자 비밀번호는 프론트엔드 소스코드나 네트워크 전송 클라이언트단에 하드코딩되지 않으며, GAS의 안전한 `Script Properties`에 보관.
   - 모든 수정/삭제 API는 세션 토큰 유효성 검증(`assertAdminSession_`)을 필수로 수행.
2. **동시성 및 데이터 무결성 (Concurrency & Data Integrity)**:
   - 다수의 관리자가 동시 편집 요청을 보낼 경우를 대비하여 `LockService.getScriptLock()`을 통한 10초 대기 상호배제(Mutex) 락 적용.
   - 각 일정마다 UUID를 생성하고 셀 메모(Note)에 `{ version: 1, items: [{ id, title }] }` JSON 메타데이터를 저장하여 삭제 시 동명이칭 일정과의 오작동 방지.
3. **반응형 웹 및 크로스 브라우징 (Responsive & Universal)**:
   - 모바일(320px~), 태블릿(640px~), 데스크톱(960px~) 전 기기 최적화.
   - `prefers-reduced-motion` 미디어 쿼리 지원으로 애니메이션 민감 사용자 배려.
   - 웹 표준 접근성 속성(`aria-live`, `aria-selected`, `aria-modal`, `role="status"`, `skip-link`) 준수.
4. **고성능 렌더링 (Performance)**:
   - 서버에서 수신된 원본 배열을 `Map<day, events[]>`로 인덱싱하여 월간/주간 뷰 렌더링 시 $O(1)$에 근접한 속도로 셀 배치 수행.

## 6. 데이터베이스(스프레드시트) 스키마 (Database Schema)

스프레드시트는 총 3종류의 시트 테이블로 구성됩니다.

### 6.1 월별 시트 (시트명: `YYYY.M` 또는 `YYYY.MM`, 예: `2026.3`)
| A열 (일) | B열 (요일) | C열 (학사일정) | D열 (off-JT) | E열 (OJT) | F열 (특별수업) | ... |
| :---: | :---: | :--- | :--- | :--- | :--- | :--- |
| `1` | `일` | 삼일절 | | | | |
| `2` | `월` | 개학식 및 입학식 | | | | |
| `3` | `화` | | 네트워크 기초 (7) | | | |
| `4` | `수` | | | 스마트공장 현장실습 (8) | | |

- **셀 값 (Value)**: 한 날짜/분류에 여러 일정이 존재할 경우 개행(`\n`)으로 구분 저장.
- **셀 메모 (Note)**: 각 일정의 고유 UUID를 JSON 객체로 보관하여 일정 삭제/수정 시 완벽한 추적성 보장:
  ```json
  {
    "version": 1,
    "items": [
      { "id": "4f9b8c2e-98b4-4b5a-93f8-d4c3821a71c8", "title": "네트워크 기초 (7)" }
    ]
  }
  ```

### 6.2 `공지사항` 시트 (D-Day와 동일한 행 단위 구조)
| A열 (공지 날짜) | B열 (공지 내용) | C열 (__id, 숨김열) |
| :--- | :--- | :--- |
| `2026-09-16` | `제4과목 내부평가` | `a1b2c3d4-...` (UUID) |
| `2026-10-12` | `SQLD 원서접수` | `e5f6g7h8-...` (UUID) |

### 6.3 `설정` 시트 (종합 텍스트 호환 유지 + 연간 목표 이수시간)
| A열 (항목) | B열 (값) | 설명 |
| :--- | :--- | :--- |
| `Notice` | `▶하계 방학(8/13) ▶개학(8/14)...` | 공지사항 종합 텍스트 (최대 500자) |
| `off-JT 목표시간` | `200` | 학년도 연간 목표 이수시간 (선택) |
| `OJT 목표시간` | `500` | 학년도 연간 목표 이수시간 (선택) |
| `방과후 목표시간` | `60` | 학년도 연간 목표 이수시간 (선택) |
| `1학기 시작` | `2026-03-02` | 학기 집계 구간 (선택) |
| `1학기 종료` | `2026-08-13` | 학기 집계 구간 (선택) |
| `2학기 시작` | `2026-08-14` | 학기 집계 구간 (선택) |
| `2학기 종료` | `2027-02-13` | 학기 집계 구간 (선택) |

- **행 위치는 자유입니다.** 1~20행 사이에서 A열 항목명으로 인식합니다(`목표` 포함 + B열 양수 → 목표 시간, `1·2학기` + `시작·종료` → 학기 구간).
- 날짜는 `2026-03-02`와 `2026. 3. 2.` 형식, 셀 서식이 날짜인 값 모두 인식합니다.
- 학기는 **시작·종료가 모두 있고 순서가 올바를 때만** 적용되며, 한쪽만 적혀 있으면 해당 학기는 기본 구분으로 동작합니다.
- **방학 처리는 날짜로 표현합니다.** `1학기 종료 8/13` → `2학기 시작 8/14`처럼 붙여 적으면 방학이 2학기에 포함되고, `7/20` → `8/17`처럼 공백을 두면 그 사이 훈련은 학기 집계에서 빠지고 **연간에만** 반영됩니다(연간 = 1학기 시작 ~ 2학기 종료).
- 아무것도 등록하지 않으면 목표 막대 없이, 월 단위 기본 구분으로 누적 수치만 표시됩니다.

### 6.4 `디데이` 시트
| A열 (목표 날짜) | B열 (디데이 명칭) | C열 (__id, 숨김열) |
| :--- | :--- | :--- |
| `2026-04-15` | `1차 도제역량평가` | `4f9b8c2e-...` (UUID) |
| `2026-06-20` | `과정평가형 자격 외부평가` | `7a8b9c0d-...` (UUID) |

#### 1) 커스텀 다이얼로그 · 토스트 시스템 (`showConfirmDialog`, `showToast`)
브라우저 기본 다이얼로그(`alert()`, `confirm()`)의 투박함과 주소 노출 문제를 해결하기 위해 구축된 자체 UI 모듈입니다:

- **위험도 구분**: `isDanger` 플래그로 삭제(레드) / 일반 확인(뉴트럴) 버튼 테마를 분기.

- **플로팅 토스트 (`showToast(message, type, duration)`)**: 비차단형(Non-blocking) 알림. `info` / `success` / `warning` / `error` 4종 테마를 지원하며 기본 3.5초 후 슬라이드 아웃과 함께 자동 소멸합니다.
- **키보드 접근성**: `Escape` 키로 취소/닫기, 모달 오픈 시 입력란 자동 포커스(`setTimeout 100ms`) 처리.

#### 2) $O(1)$ 데이터 인덱싱 (`buildEventIndex`)
```javascript
function buildEventIndex(data) {
  return Object.entries(data).reduce((index, [sheetKey, events]) => {
    const byDay = new Map();
    (events || []).forEach((event) => {
      const day = Number(event.day);
      if (!byDay.has(day)) byDay.set(day, []);
      byDay.get(day).push(event);
    });
    index[sheetKey] = byDay;
    return index;
  }, {});
}
```
수백 건의 일정이 등록되어 있어도 각 날짜 셀을 렌더링할 때 배열 전체를 매번 순회하지 않고, `sheetKey`와 `day`를 키로 하여 $O(1)$ 속도로 일정을 추출합니다.

#### 3-1) 누적 집계 파이프라인 (`classifyEvent`, `accumulateEventStats`, `computeStatsForRange`)
- 분류 판정(`classifyEvent`)과 집계 누적(`accumulateEventStats`)을 **한 곳으로 모아 화면 기준 집계와 누적 집계가 같은 규칙을 공유**합니다. 두 곳에 규칙을 복제하면 통계가 서로 어긋나기 때문입니다.
- `computeStatsForRange`는 일정마다 `YYYY-MM-DD`를 만들어 구간과 문자열 비교하므로, **월 중간에 걸친 학기 경계와 연도 경계(`2026.12 → 2027.1`)를 모두 정확히 처리**합니다.
- 집계 구간은 `statsRangeFor()`가 결정합니다. `설정` 시트의 학기 날짜(`termRangeFromSheet`)를 우선 쓰고, 없거나 학년도가 맞지 않으면 월 단위 기본 구분(`defaultTermRange`)으로 폴백하며, 어느 쪽을 썼는지 캡션에 표시합니다.
- 캘린더 렌더러가 넘겨준 화면 기준 수치는 `screenStats`에 보관되고, `renderDashboard()`가 선택된 범위에 따라 화면 기준 / 누적 중 무엇을 표시할지 결정합니다. 덕분에 **연간 범위에서는 월간↔주간 뷰를 전환해도 수치가 고정**됩니다.

#### 3) 이수시간 파싱 및 정밀 D-Day 산출 (`getEventHours`, `processEventsToCell`, `calculateDDay`)
- **이수 시간 (`getEventHours(ev, defaultHours)`)**: 서버가 숫자형 `ev.hours`를 내려주면 그 값을 우선 사용하고, 없으면 일정 제목에서 정규식 `/\((\d+)\)/`으로 **첫 번째 괄호 숫자**를 추출합니다. 이 때문에 `OJT(5) 제4과목평가`처럼 괄호 뒤에 부가 설명이 붙어도 5시간이 정확히 반영됩니다. 둘 다 없으면 기본값(off-JT: 7시간, OJT: 8시간, 방과후 수업: 2시간)을 적용합니다.
- **키워드 기반 분류 엔진 (`processEventsToCell`)**: 분류명과 일정명에서 공백·하이픈을 제거하고 대문자로 정규화한 뒤(`replace(/[-\s]/g, '').toUpperCase()`) `OFFJT` / `OJT` / `특별수업` / `방과후` 포함 여부로 배지 색상을 결정합니다. `재량휴업일`, `휴업일`, `공휴일`, `대체공휴일`, `국가공휴일`, `국경일`, `법정공휴일`, `명절` 키워드는 **최우선(holiday)으로 판정**되며 이수시간 집계에서 제외됩니다. 즉 시트 헤더가 아니라 텍스트만으로도 자동 분류가 되므로, 관리자가 신규 카테고리 열을 추가해도 색상 코딩이 깨지지 않습니다.
- **고유 훈련일 수 산출**: `Set` 자료구조를 사용하여 같은 날 여러 개의 off-JT, OJT, 방과후 수업 일정이 있더라도 실제 교육/훈련 일수가 중복 카운트되지 않도록 정합성을 보장합니다. 집계는 **필터 적용 이전**에 수행되므로, 카테고리 칩으로 화면을 좁혀도 해당 기간의 총 이수시간 통계는 변하지 않습니다.
- **D-Day 계산**: 오늘 자정을 기준으로 등록된 마일스톤과의 밀리초 차이를 `Math.ceil`하여 `D-Day` 또는 `D-N`을 실시간 계산하며, 뷰 전환·기간 이동 때마다 `renderActiveView()` 말미에서 재계산됩니다.

#### 4) 공지 배너 자동 만료 필터 (`isNoticeItemInCurrentMonth`, `renderNotice`)
- `설정!B1`의 종합 공지 텍스트를 `▶ ▷ ► •` 마커(없으면 개행) 기준으로 쪼갠 뒤, 각 항목에서 `(?:(\d{4})[-/.년])?(\d{1,2})[-/.월](\d{1,2})일?` 패턴으로 날짜를 추출합니다.

- **표시 규칙**: ① 날짜가 없는 상시 공지는 항상 표시 ② 종료일이 오늘 이전이면 숨김 ③ 일정 구간이 현재 시스템 월과 겹칠 때만 표시. 표시할 항목이 하나도 없으면 `이번 달 진행 예정인 공지사항 일정이 없습니다.` 문구로 대체됩니다.

#### 1) 요청 라우팅 및 락 제어 (`doGet`, `doPost`)
- `doGet`은 시트명이 `YYYY.M` / `YYYY.MM` 정규식(`/^(\d{4})\.(0?[1-9]|1[0-2])$/`)에 일치하는 모든 시트를 순회하여 한 번의 응답에 전체 학년도 일정을 담아 반환합니다. 시트 키는 `2026.03` → `2026.3`으로 정규화되어 프론트엔드 인덱스와 일치합니다.
- `doPost`는 `verify`(로그인)와 `logout`을 제외한 **모든 액션에 대해 `assertAdminSession_(payload.token)`을 선행 호출**한 뒤, `LockService.getScriptLock()`을 취득하고 `try/finally`로 반드시 해제합니다. 동시 쓰기 요청 발생 시 최대 10초 대기 큐를 형성하여 스프레드시트의 Race Condition을 원천 방지합니다.
- 어떤 예외가 발생해도 HTTP 오류 대신 `{ success: false, message }` JSON을 반환하여 프론트엔드가 일관되게 토스트로 처리할 수 있습니다.

#### 2) 보안 세션 토큰 관리 (`createAdminSession_`, `assertAdminSession_`)
- `ADMIN_PASSWORD` 일치 시 `Utilities.getUuid()` 2개를 이어 붙인 68자 토큰을 발급하고 `CacheService.getScriptCache()`에 30분(`SESSION_TTL_SECONDS = 1800`) 동안 보관합니다.
- 스크립트 속성에 비밀번호가 등록되어 있지 않으면 로그인을 아예 거부하므로, **설정 누락 상태가 무인증 통과로 이어지지 않습니다.**
- 인가되지 않은 토큰으로 데이터 변경 API 호출 시 예외를 던져 작업을 즉각 차단합니다.

#### 3) 셀 값과 Note 메타데이터의 양방향 동기화 (`readCellEvents_`, `writeCellEvents_`)
```javascript
// 읽기: 셀 텍스트를 개행으로 분해하고, Note의 JSON 배열과 인덱스·제목이 모두 일치할 때만 UUID 승계
const id = saved && saved.title === title && isEventId_(saved.id)
  ? saved.id
  : legacyEventId_(sheetId, row, column, index);   // 'legacy:시트ID:행:열:인덱스'

// 쓰기: 텍스트는 \n 결합, 메타데이터는 Note에 JSON 저장 (빈 배열이면 셀·노트 동시 클리어)
cell.setValue(events.map((e) => e.title).join('\n'));
cell.setNote(JSON.stringify({ version: 1, items: events.map((e) => ({ id: e.id, title: e.title })) }));
```
- Note가 없거나 손상된 기존 수기 입력 데이터도 **`legacy:` 합성 ID로 자동 승격**되므로, 마이그레이션 없이 기존 스프레드시트를 그대로 연결할 수 있습니다.
- 삭제(`deleteEvent_`)는 `id`와 `title`이 **동시에** 일치하는 항목만 제거하므로, 동일한 이름의 일정이 여러 건 있어도 안전하게 단건 삭제가 가능합니다.
- 수정(`updateEvent_`)은 기존 셀에서 제거 후 새 셀에 추가하는 방식이라 **날짜·분류를 넘나드는 이동까지 동일 UUID를 유지**합니다.

#### 7) 지난 디데이·공지 행 자동 숨김 (`hidePastDatedRows`, `hidePastRowsInSheet_`)
- `디데이`·`공지사항` 시트의 A열 날짜를 `storedDateToIso_()`로 해석해 오늘(스프레드시트 표준시) 이전이면 해당 행을 숨깁니다. ISO(`yyyy-MM-dd`) 형식이라 문자열 비교만으로 순서가 보장됩니다.
- **날짜가 없는 상시 공지, 해석 불가한 값, 내용이 빈 행은 숨기지 않습니다.** 의미를 알 수 없는 데이터를 감추지 않는다는 원칙입니다.
- 연속된 행은 하나의 구간으로 묶어 `hideRows(start, count)`를 호출하므로, 행이 많아도 API 호출 수가 구간 수만큼으로 유지됩니다.
- 행을 숨겨도 `getValues()` 결과와 행 번호는 변하지 않으므로 `findNoticeRow_` / `findMilestoneRow_` 기반의 행 단위 수정·삭제가 영향을 받지 않습니다.
- 날짜는 매일 지나가므로 트리거는 `everyDays(1).atHour(1)`로 **매일** 실행합니다.

#### 6) 지난 월 시트 자동 숨김 (`hideOldMonthlySheets`, `parseMonthlySheetName_`)
- 시트명을 `parseMonthlySheetName_()`으로 파싱해 **연·월을 `연*12+월` 통산 월수로 환산**한 뒤 이번 달과 비교합니다. 문자열로 비교하면 `2026.9 > 2026.10`이 되어 순서가 뒤집히므로 반드시 숫자로 환산합니다.
- 기준 시각은 `Utilities.formatDate(new Date(), ss.getSpreadsheetTimeZone(), 'yyyy-MM')`로 **스프레드시트 표준시**를 따릅니다(스크립트 실행 지역과 무관하게 동작).
- `ScriptApp.newTrigger('hideOldMonthlySheets').timeBased().onMonthDay(1).atHour(1)`로 매월 1일 자동 실행하며, 설치 시 동일 핸들러의 기존 트리거를 먼저 제거해 중복을 방지합니다.
- 숨김은 시트 탭 정리 용도일 뿐이며 `doGet`은 숨긴 시트도 그대로 읽습니다. 월별 시트가 아닌 시트는 제외하고, 보이는 시트가 1개 남으면 중단하며, 활성 시트는 다른 시트로 포커스를 옮긴 뒤 숨깁니다.

#### 4) 시트 자동 생성 및 공지 마이그레이션 (`onOpen`, `createNoticeSheetNow`, `readNotices_`)
- 스프레드시트를 열면 `onOpen`이 상단에 **`📅 캘린더 관리` 커스텀 메뉴**를 설치하고, `📢 공지사항 시트 자동 생성 및 동기화` 항목으로 수동 마이그레이션을 실행할 수 있습니다.
- `readNotices_`는 `공지사항` 시트가 비어 있으면 `설정!B1`의 종합 텍스트를 `parseNoticeItemsFromRaw_`로 파싱하여 **[날짜 / 내용 / UUID] 행으로 자동 승격**합니다. 반대로 행 단위 CRUD가 일어나면 `syncNoticeSheetToConfig_`가 `▶제목(M/D)` 형식의 종합 텍스트를 재생성하여 `설정!B1`에 되돌려 씁니다 (양방향 동기화).
- 월별 시트(`getOrCreateMonthlySheet_`)와 분류 열(`findOrCreateEventColumn_`), 일자 행(`findOrCreateDayRow_`)은 일정 등록 시 **없으면 즉시 생성**되므로, 관리자는 새 학년도 시트를 미리 만들어 둘 필요가 없습니다.

#### 5) 입력 검증 계층 (`requireText_`, `requireInteger_`, `requireEventType_`, `parseIsoDate_`)
- 일정 분류는 화이트리스트(`ALLOWED_EVENT_TYPES = ['학사일정', 'off-JT', 'OJT', '특별수업', '국가공휴일', '휴업일']`)에 포함되거나, **이미 월별 시트의 열로 존재하는 분류**(`isExistingSheetType_`)만 허용합니다. 덕분에 시트에 직접 추가한 사용자 정의 분류의 일정도 수정할 수 있으면서, API로 임의의 새 열이 생성되는 것은 차단됩니다.
- 문자열은 CRLF 정규화 → 트림 → 줄바꿈 금지(공지 본문 제외) → 길이 제한(제목 200자 / 공지 500자) 순으로 검증합니다.
- 날짜는 `YYYY-MM-DD` 형식에 더해 **2000~2100년 범위와 해당 월의 실제 말일까지 확인**(`isValidDateParts_`)하므로 `2026-02-30` 같은 값이 시트에 기록되지 않습니다.
- 이수 시간은 1~24 정수만 통과합니다.

## 9. 배포 및 설치 가이드 (Deployment Guide)

### Step 1. 구글 스프레드시트 준비
1. 새 Google Spreadsheet를 생성합니다.
2. 아래 시트를 생성합니다:
   - `설정`: A1에 `Notice`, B1에 초기 공지 입력
   - `디데이`: A1에 `목표 날짜`, B1에 `디데이 명칭`, C1에 `__id` (C열은 숨김 처리)
   - `2026.3` (현재 월 시트): A1에 `일`, B1에 `요일`, C1~H1에 카테고리 헤더(`학사일정`, `off-JT`, `OJT`, `특별수업`, `국가공휴일`, `휴업일`) 작성
   - `공지사항` 시트는 **수동 생성이 필요 없습니다.** 최초 `doGet` 호출 시 `설정!B1` 내용을 파싱하여 자동 생성·마이그레이션되며, 스프레드시트 상단 `📅 캘린더 관리 > 📢 공지사항 시트 자동 생성 및 동기화` 메뉴로도 즉시 실행할 수 있습니다.
   - 월별 시트·분류 열·일자 행은 관리자가 일정을 등록할 때 없으면 자동 생성되므로, 다음 학년도 시트를 미리 만들어 둘 필요가 없습니다.
3. 상단 메뉴에서 `확장 프로그램` > `Apps Script`를 클릭합니다.

### Step 2. Apps Script 소스코드 적용 및 비밀번호 등록
1. 열린 스크립트 편집기에 본 프로젝트의 `code.gs` 내용 전체를 붙여넣고 저장합니다.
2. 좌측 메뉴의 **프로젝트 설정(톱니바퀴 아이콘)**을 클릭합니다.
3. **스크립트 속성** 섹션에서 **스크립트 속성 추가**를 클릭합니다:
   - **속성**: `ADMIN_PASSWORD`
   - **값**: `원하는 관리자 비밀번호 입력 (예: 1234)`
4. 속성을 저장합니다.

### Step 3. 웹 앱 배포 (Web App)
1. 편집기 우측 상단의 **배포** > **새 배포**를 클릭합니다.
2. 유형 선택: **웹 앱(Web App)**
   - **설명**: `v1.5`
   - **다음 사용자로 실행**: `나(내 계정)`
   - **액세스 권한이 있는 사용자**: `모든 사용자(Anyone)`
3. **배포**를 누르고 접근 권한을 승인합니다.
4. 생성된 **웹 앱 URL (`https://script.google.com/macros/s/.../exec`)**을 복사합니다.

### Step 3-1. (선택) 지난 데이터 자동 숨김 설정
학년도가 쌓이면 월별 시트 탭과 지난 디데이·공지 행이 계속 늘어납니다. 스프레드시트 상단 `📅 캘린더 관리` 메뉴에서 두 종류의 정리를 각각 켤 수 있습니다.

#### 🗂️ 지난 월 시트 정리
| 메뉴 | 동작 |
| :--- | :--- |
| 지금 숨기기 | 이번 달보다 이전인 `YYYY.M` 시트를 즉시 숨김 |
| 모두 다시 표시 | 숨겨둔 월별 시트를 모두 복원 |
| ⏰ 매월 1일 자동 숨김 켜기 | 매월 1일 새벽 1시경 실행되는 트리거 설치 |
| ⏹️ 자동 숨김 끄기 | 트리거 해제 |

#### 📋 지난 디데이·공지 행 정리
| 메뉴 | 동작 |
| :--- | :--- |
| 지금 숨기기 | `디데이`·`공지사항` 시트에서 날짜가 오늘보다 이전인 행을 즉시 숨김 |
| 모두 다시 표시 | 두 시트의 모든 행을 복원 |
| ⏰ 매일 자동 숨김 켜기 | 매일 새벽 1시경 실행되는 트리거 설치(날짜는 매일 지나가므로 월 단위가 아닌 **일 단위**) |
| ⏹️ 자동 숨김 끄기 | 트리거 해제 |

> **중요**: 시트·행 숨김은 모두 **스프레드시트 편집 화면의 정리 용도**입니다. `getSheets()`와 `getRange().getValues()`는 숨긴 시트·행도 그대로 반환하므로 **웹 캘린더의 표시와 수정 동작에는 전혀 영향이 없습니다.** 지난 일정도 캘린더에서 평소대로 조회·편집됩니다.
>
> **안전장치**
> - 월별 시트(`YYYY.M` / `YYYY.MM`) 외의 시트(`설정`, `디데이`, `공지사항` 등)는 시트 숨김 대상에서 제외
> - 보이는 시트가 1개만 남으면 중단(스프레드시트는 모든 시트를 숨길 수 없음), 활성 시트는 포커스를 옮긴 뒤 숨김
> - **날짜가 없는 상시 공지와 날짜를 해석할 수 없는 행은 숨기지 않음**, 헤더(1행)는 항상 유지
> - 행을 숨겨도 행 번호는 밀리지 않으므로 기존의 행 단위 수정·삭제 로직이 영향을 받지 않음
> - 두 트리거 모두 설치 시 동일 핸들러의 기존 트리거를 먼저 제거해 중복을 방지하며, 최초 설치 시 Apps Script 권한 승인이 한 번 필요합니다.

### Step 4. 프론트엔드 연동 및 실행
1. 프로젝트 루트의 `school_project_05_gas.json` 파일을 열고 복사한 URL을 입력합니다:
   ```json
   {
     "gas_url": "https://script.google.com/macros/s/AKfycb.../exec"
   }
   ```
2. 웹 서버(VS Code Live Server, GitHub Pages 등)로 `index.html`을 실행합니다.

#### P1 — 공지/디데이 삭제 버튼 동작 불가 (런타임 오류) · 해결
- **위치**: `index.html` `deleteNoticeItem()`, `deleteDDay()`

#### P3 — 공지 저장 시 UUID 재발급 · 해결

#### P4 — 동명 일정 수정 시 대상 오인 가능성 · 해결

#### P16 — 🔴 일정표 저장 결과가 백지 이미지로 나옴 · 해결

- **내보낸 이미지에 조작용 UI가 함께 담김**: 캡처 대상이 `#calendar-workspace` 전체이므로 뷰 탭(`월간 보기/1주간/2주간`), 이전·다음 화살표, `오늘` 버튼, 필터 칩, 그리고 모바일의 `💡 모바일 팁` 안내까지 이미지에 포함됩니다. 특히 모바일 팁은 앱 사용자를 위한 안내라 공유용 이미지에는 불필요합니다. `onclone`에서 이 요소들을 숨기면 달력 본문만 깔끔하게 내보낼 수 있습니다(표시 내용에 대한 판단이 필요해 임의로 적용하지 않음).

### ⚪ 참고 사항 (설계상 트레이드오프)
- **전체 데이터 일괄 전송**: `doGet`이 모든 월 시트를 한 번에 반환합니다. 현재 규모(학년도 단위 수백 건)에서는 문제없으나 수년치가 누적되면 월 단위 페이징이 필요합니다.
- **낙관적 갱신 없음**: 모든 관리자 작업 후 `loadServerData()`로 전체를 재조회합니다. 구현이 단순하고 정합성이 확실한 대신 왕복 지연이 발생합니다.
- **관리자 토큰의 `localStorage` 보관**: 편의성을 위한 선택으로, XSS가 발생하면 토큰이 탈취될 수 있습니다. 다만 모든 렌더링 경로가 `textContent` 또는 `escapeHtml()`을 사용하고 있어 현재 주입 지점은 확인되지 않았으며, 토큰 수명도 30분으로 제한됩니다.
- **`0821/` 아카이브**: 현재 배포본과 연동되지 않는 과거 스냅샷입니다. 수정 시 루트의 `index.html` / `code.gs`만 편집하면 됩니다.
