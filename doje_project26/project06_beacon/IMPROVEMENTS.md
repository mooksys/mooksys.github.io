### P1-2 — 날짜 선택기 폴백

`index.html`에 투명 오버레이 `<input type="date" id="nativeDatePicker">`를 넣고,
`typeof flatpickr === "undefined"`일 때 `enableNativeDatePickerFallback()`이
이를 노출합니다. `changeDate()`의 이전/다음일 이동과도 `syncNativeDatePicker()`로
동기화됩니다.

**여전히 배포 전 학교 네트워크에서 `cdn.jsdelivr.net` 접속을 확인하세요.**
폴백은 기능을 지켜줄 뿐이고, 폰트와 달력 디자인은 CDN이 막히면 기본 모양이 됩니다.

### P1-3 — 페퍼 백업

`manualShowPasswordPepper()`가 2단계 확인 후 페퍼를 보여줍니다.
스프레드시트 편집 권한자는 Apps Script 편집기에서 스크립트 속성을 직접 볼 수
있으므로 이 메뉴가 권한을 새로 넓히지는 않습니다.

**종이나 학교 문서 보관 체계에 오프라인으로 1부 보관하세요.**

### P1-4 — 변동 공휴일

`VARIABLE_HOLIDAYS_BY_YEAR` 상수에 연도별 등록 후보를 두고,
`manualRegisterVariableHolidays()`가 `BlockedDates` 시트에 넣습니다.
이미 있는 날짜는 교사가 손댔을 수 있으므로 건너뜁니다.

최종 판단은 `BlockedDates` 시트가 하므로, 상수는 '자동 결정'이 아니라
'입력 보조'입니다. 등록 후 `날짜 차단` 화면에서 확인하세요.

2026년에 **실습요일(화·수·목)에 실제로 걸리는 공휴일은 두 날뿐**입니다.

| 날짜 | 요일 | 사유 |

| 2026-06-03 | 수 | 임시공휴일 (제9회 전국동시지방선거) |
| 2026-09-24 | 목 | 추석 연휴 |

나머지 2026년 공휴일(3/1·3/2 대체, 5/24·5/25 대체, 6/6, 7/17 제헌절, 8/15·8/17 대체,

### P2-5 — 시간대 처리

`formatKST(fmt, instant)`를 도입하고, `Utilities.formatDate(nowKST(), 'GMT+9', ...)`
형태의 이중 변환 호출부를 전부 정리했습니다. `nowKST()`는 요일·시각 '필드' 접근용으로만
남기고, 같은 순간을 필드와 문자열로 함께 써야 하는 `recordAttendance()`에서는
하나의 `instant`에서 둘 다 파생시켜 자정 경계에서 갈라지지 않게 했습니다.

### P2-6 — 월간 레포트 부분 읽기

`readAttendanceByMonth()`가 날짜 열 1개만 훑어 해당 월의 행 범위를 좁힌 뒤
그 구간만 8열로 읽습니다. 기존 `readAttendanceByDate()`와 같은 방식입니다.
공결 등록처럼 지난 날짜가 뒤늦게 append 되어 순서가 어긋나 있어도, 최초·최종
위치로 구간을 잡고 읽은 뒤 한 번 더 걸러서 누락되지 않습니다.

### P3-11 — 테스트

`tests.gs`에 시트·세션에 의존하지 않는 순수 함수 테스트 20건을 넣었습니다.
Apps Script 편집기에서 `runAllTests`를 실행하면 [실행 로그]에 결과가 나오고,
실패가 있으면 예외로 끝납니다. `doPost`에서 호출되지 않으므로 웹앱 동작에는
영향이 없습니다.

단일 파일 방침과 충돌하지 않습니다 — 배포 단위는 여전히 Apps Script 프로젝트
하나이고, 프론트(`index.html`)는 그대로 한 파일입니다. 운영 코드에 테스트를
섞고 싶지 않아 `code.gs`와 분리했을 뿐이고, 원치 않으면 파일을 지워도 됩니다.

검증 시 **스크립트 시간대를 UTC·America/Los_Angeles·Pacific/Kiritimati·Asia/Seoul로
바꿔가며 전부 통과**하는 것을 확인했습니다. P2-5 시간대 수정이 실제로 시간대에
무관해졌다는 근거입니다.

### P4-13 — 예외 메시지

`error.stack`은 `Logger.log`로 남깁니다. Apps Script 편집기의 [실행] 목록에서
확인할 수 있으므로 디버깅 능력은 오히려 좋아집니다.

### P4-14 — 요청 빈도 제한

`exceedsRateLimit(action, id)`를 `doPost`의 세션 검증 **앞**에 붙였습니다.
토큰 없이 퍼붓는 호출도 걸러야 해서 앞쪽에 둡니다.
`CacheService` 고정 창(60초) 방식이고, 액션별로 per-id / 전체 한도를 둡니다.

| 액션 | per-id | 전체 | 정상 사용량 |
|---|---:|---:|---|
| `login` | 10 | 200 | 접속당 1~2회 |
| `getConfig` | 60 | 300 | 접속당 1회 |
| `recordAttendance` | 10 | 200 | 학생당 하루 2회 |
| 그 외(`_default`) | 60 | 600 | 대시보드 폴링 분당 2회 |

**한도는 정상 사용의 몇 배로 잡았습니다.** 목적이 악용 차단이지 정밀 제어가
아니기 때문입니다. 테스트 `rateLimit (정상 사용 허용)`이 이 성질을 지킵니다 —
한도를 조이면 이 테스트가 먼저 깨집니다.

알고 있어야 할 한계는 셋입니다.

- **GAS는 클라이언트 IP를 주지 않습니다.** id 기준으로만 나눌 수 있고, 로그인 전
  요청은 전부 `anon` 묶음을 공유합니다. 무인증 액션 한도를 크게 잡은 이유입니다.
- **캐시 읽기→쓰기가 원자적이지 않아** 동시 요청에서는 실제보다 적게 셉니다.
  막으려면 잠금이 필요한데 그러면 이 함수가 병목이 됩니다(P4-15와 정면 충돌).
- **`CacheService`는 값을 버릴 수 있습니다.** 못 세면 통과시킵니다(fail-open).
  잠깐의 과다 호출보다 정상 사용자를 막는 쪽이 더 나쁩니다.

### P4-15 — 전역 락

`verifySessionToken`의 **읽기**를 잠금 밖으로 뺐습니다. 토큰 조회는 멱등이고
살짝 오래된 값을 읽어도 결론이 달라지지 않습니다. 시트를 **쓰는** 두 경우
(만료 행 삭제, 슬라이딩 갱신)만 잠금 안에서 처리하고, 쓰기 전에 토큰 셀을 다시
읽어 그 사이 행이 밀렸는지 확인합니다. 두 쓰기 모두 실패해도 판정 결과에는
영향이 없어 조용히 넘어갑니다.

결과적으로 **인증 요청당 전역 락 획득이 2회 → 대부분 0회**가 됩니다
(슬라이딩 갱신이 필요한 10분마다 1회, 실제 작업이 잠금을 쓰면 그때 1회).

### P3-8 — 데드 코드 삭제

`verifyAdminRole()`을 지우고, 그 자리에 **왜 이 방식을 쓰지 않는지**를 주석으로
남겼습니다. 함수만 조용히 지우면 나중에 누군가 같은 걸 다시 만들 수 있습니다.

교사 전용 액션을 새로 추가할 때는 시트의 ROLE을 다시 읽지 말고
`doPost`의 기존 분기와 똑같이 `verifySessionToken(..., '교사')`을 쓰세요.

### P3-9 — 헤더 주석 정정

`code.gs` 파일 헤더를 실제 동작에 맞게 다시 썼습니다.
"Google Drive 자동 저장 + 다운로드 URL 반환"은 사실이 아니었습니다 —
서버는 HTML 문자열만 반환하고 PDF 저장은 브라우저 인쇄가 합니다.

`fileName`의 `.pdf` 확장자는 **그대로 두었습니다.** 조사해 보니 오류가 아니라
의도된 값입니다. `buildReportHtml()`의 `<title>`이 브라우저 "PDF로 저장"의 기본
파일명이 되므로, `fileName`은 교사가 실제로 받게 될 이름을 미리 보여주는 화면
라벨입니다. 다만 "파일이 생성된다"는 오해를 막는 주석을 붙였습니다.

(반환 필드명 `fileName` 자체는 바꾸지 않았습니다. 프론트 사용처가 한 곳뿐이라
변경은 쉽지만, API 응답 형태를 건드리는 일이라 별도 판단이 필요합니다.)

### P2-7 — 팝업 통일

`alert()` 11곳을 `showAlert()`로 교체했습니다. 세션이 끊기는 경로

## 진단 정정

검토 초판에서 제가 잘못 적은 부분입니다. 기록을 위해 남깁니다.

**① P2-5의 원인을 반대로 짚었습니다.**
초판은 `getScheduledReportDates()`의 `new Date()`를 문제로 지목했습니다.
실제로는 그쪽이 **옳은** 코드입니다 — `new Date()`는 절대 시각이고
`Utilities.formatDate(..., 'GMT+9', ...)`가 올바르게 변환합니다.
진짜 문제는 `formatDate(nowKST(), 'GMT+9', ...)` 형태로, `nowKST()`가 이미 옮겨둔
벽시계를 한 번 더 변환하는 **이중 변환**이었습니다. 스크립트 시간대가
`Asia/Seoul`이면 두 변환이 상쇄되어 증상이 없고, 아니면 날짜가 어긋납니다.
즉 '활성 버그'가 아니라 '시간대 설정에 의존하는 잠복 취약점'이었습니다.

**② P1-2의 증상을 과장했습니다.**
초판은 "`ReferenceError`로 교사 달력이 죽는다"고 했지만, `showAdmin()`에는 이미
`typeof flatpickr !== "undefined"` 가드가 있었습니다. 실제 증상은 오류 없이
**날짜 선택 칩이 조용히 아무 반응도 하지 않는 것**이었습니다(이전/다음일 버튼은 동작).
오류보다 알아채기 어려운 형태라 우선순위 자체는 유지했습니다.
