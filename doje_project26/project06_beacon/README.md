# 2026 Doje Beacon System

성일정보고등학교 도제반(3-12) 현장실습 출결 관리 시스템.

학생은 모바일/PC에서 입실·퇴실을 기록하고, 교사는 실시간 대시보드로 지각·미퇴실·미입력자를 확인하며 월간 출석부를 A4 1장으로 인쇄합니다.
학생은 [내 출결](#내-출결-학생-본인-월간-조회)에서 자기 출석률을 직접 확인하고,
실습일 마감 후에는 그날의 결석·지각·미퇴실이 [교사 메일로 자동 발송](#일일-마감-알림-메일)됩니다.

- **Frontend**: 단일 HTML SPA (Vanilla JS, 빌드 도구 없음)
- **Backend**: Google Apps Script 웹앱 (`code.gs`)
- **Database**: Google Spreadsheet 4개 시트 + Script Properties

상세 요구사항은 [prd.md](prd.md)를 참조하세요.

## 파일 구조

```
project06_beacon/
├─ index.html                  프론트엔드 전체 (HTML+CSS+JS 단일 파일, 7,700여 줄)
├─ code.gs                     GAS 백엔드 전체 (3,000여 줄)
├─ tests.gs                    테스트 53건 (Apps Script 편집기에서 runAllTests 실행)
├─ project26_05_gas_url.json   GAS 웹앱 배포 URL
├─ prd.md                      요구사항 명세서
├─ IMPROVEMENTS.md             개선 과제 목록 (반영 완료 / 남은 항목)
├─ DESIGN-REVIEW.md            디자인 일관성 점검 결과
└─ SCHOOL-YEAR-PLAN.md         학년도 분리 설계 배경과 결정 기록
```

`index.html`과 `code.gs`는 **의도적으로 단일 파일**입니다. 배포가 "파일 하나를
올린다"로 끝나는 것이 이 프로젝트의 장점이라 쪼개지 않습니다
(자세한 내용은 [IMPROVEMENTS.md](IMPROVEMENTS.md) P3-10).

외부 의존성인 Pretendard 폰트와 Flatpickr(v4.6.13)는 `cdn.jsdelivr.net`에서 로드합니다
(`index.html` `<head>` 참조). 빌드·설치 단계가 없으며 `index.html`을 그대로 서빙하면 됩니다.

## 배포 방법

### 1. 스프레드시트 준비

**시트는 학년도별로 나뉩니다** — `Users_2026` / `Attendance_2026` 처럼
연도를 뒤에 붙입니다. 자세한 이유는 [학년도 관리](#학년도-관리)를 보세요.

`Users_YYYY`와 `Attendance_YYYY`는 **직접 만들거나**
`🎓 새 학년도 시작` 메뉴로 만듭니다.
`BlockedDates`와 `Sessions`는 학년도 공용이며 첫 요청에서 자동 생성됩니다.

`Users_YYYY` 시트 1행에 헤더를 넣고, 2행부터 교사 계정을 최소 1개 등록합니다.
(학생 계정은 배포 후 교사 화면에서 등록하면 됩니다.)

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| `ID` | `NAME` | `ROLE` | `PW` | `IN_TIME` | `OUT_TIME` |
| `teacher1` | 홍길동 | `교사` | `1234` | | |

`ROLE`은 `학생` 또는 `교사` 두 값만 유효합니다. `PW`에 평문 `1234`를 넣어두면
첫 로그인 시 자동으로 해시 체계로 승급되고 비밀번호 변경이 강제됩니다.
G~J열(`FAIL`·`LOCK`·`SALT`·`MUST_SETUP`)은 첫 요청에서 자동 추가되므로 비워두세요.

`Attendance_YYYY` 시트 1행 헤더:

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| `TIME` | `DATE` | `DAY` | `ID` | `NAME` | `TYPE` | `STD_TIME` | `STATUS` |

시트를 만든 뒤 **`📅 학년도 설정/확인` 메뉴로 활성 학년도를 지정해야** 앱이 동작합니다.
지정 전에는 모든 요청이 "학년도가 설정되지 않았습니다"로 거부됩니다.

### 2. Apps Script 배포

1. 스프레드시트에서 **확장 프로그램 → Apps Script**
2. `code.gs` 내용을 붙여넣고 저장
3. **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자** ← 학생 브라우저가 직접 호출하므로 필수
4. 발급된 `/exec` URL을 복사

### 3. 프론트엔드 연결

`project26_05_gas_url.json`에 URL을 기록합니다.

```json
{
  "api_url": "https://script.google.com/macros/s/AKfycb.../exec"
}
```

`index.html`과 이 JSON 파일을 같은 경로에 두고 **HTTP로 서빙**합니다.
(`file://`로 직접 열면 JSON fetch가 차단되어 로그인 화면에서 멈춥니다.)

### 4. 트리거 등록 (권장)

스프레드시트를 새로고침하면 상단에 **`출결 관리`** 메뉴가 나타납니다.
아래 두 가지를 한 번씩 실행해두면 됩니다.

| 메뉴 | 효과 |
|---|---|
| `세션 자동 정리 트리거 등록 (1회)` | 만료 세션이 매일 새벽 3시에 자동 정리됩니다 |
| `📧 일일 알림 트리거 등록 (1회)` | 실습일 18:30에 그날 출결 요약 메일이 자동 발송됩니다 |

> ⚠️ **스크립트 시간대가 `Asia/Seoul`이어야 합니다.**
> GAS 시간 기반 트리거는 KST가 아니라 *스크립트 시간대*를 따릅니다.
> 다르면 18:30이 한국 시간 18:30이 아니게 되므로,
> 알림 트리거 등록 메뉴가 이를 검사해 경고창으로 알려줍니다.
> Apps Script 좌측 **프로젝트 설정 → 시간대**에서 바꾼 뒤 다시 등록하세요.

## 일일 마감 알림 메일

실습일(화·수·목) 업무 마감 후, 그날의 **결석·지각·미퇴실·조퇴·공결**을
교사에게 메일 한 통으로 보냅니다. 대시보드를 열지 않은 날에도 놓치는 학생이
없게 하는 안전망입니다.

### 설정

1. `출결 관리` → **`📧 알림 받을 메일 주소 설정`** — 쉼표로 여러 명 지정 가능.
   비워두면 **스크립트 소유자(배포한 교사)** 주소로 보냅니다.
2. `출결 관리` → **`📧 오늘 마감 알림 지금 보내기`** 로 먼저 시험 발송해보세요.
   (수동 실행은 "이미 보냈음" 검사를 건너뛰므로 몇 번이든 다시 보낼 수 있습니다.)
3. `출결 관리` → **`📧 일일 알림 트리거 등록 (1회)`**

### 보내지 않는 날

아래에 해당하면 **메일을 보내지 않고** 실행 로그에 이유만 남깁니다.

- 화·수·목이 아닌 날 / 1~2월(OJT 비운영)
- 고정 공휴일 · 교사가 차단한 날
- 업무 마감(`REPORT_DAY_CLOSE_MINUTES`, 18:00) 이전

판정은 월간 레포트와 **같은 함수**(`getScheduledReportDates`)가 합니다.
레포트에는 결석인데 메일은 조용한 식으로 어긋나지 않습니다.

### 집계 규칙

| 분류 | 조건 |
|---|---|
| 결석 | 그날 `입실` 기록이 없음 |
| 지각 | `입실` 상태가 `지각` (안내문에 `+N분` 표기) |
| 미퇴실 | `입실`은 있으나 `퇴실` 기록이 없음 |
| 조퇴 | `퇴실` 상태가 `조퇴` |
| 공결 | `입실` 상태가 `공결`로 시작 — **결석·미퇴실 어디에도 넣지 않습니다** |

**퇴반 학생은 집계에서 빠집니다**(`isEnrolledOn`). 빠지지 않으면 그만둔 학생이
매주 결석자로 메일에 실립니다.

### 쿼터와 권한

- 무료 Google 계정의 `MailApp` 한도는 **일 100통**입니다. 하루 1통이라 여유가 큽니다.
  발송 전 `getRemainingDailyQuota()`로 남은 수량을 확인하고, 부족하면 보내지 않습니다.
- **`MailApp` 사용으로 메일 발송 권한이 새로 필요합니다.** `code.gs`를 올린 뒤
  메뉴를 처음 실행하면 권한 승인 화면이 뜹니다. 승인해야 트리거가 동작합니다.

## 학년도 관리

**학번은 해마다 재사용됩니다.** `31201`은 3학년 12반 1번이라는 뜻이라,
2026년 학생이 졸업하면 2027년 신입생이 같은 번호를 받습니다.

그런데 계정 관리 함수들(`findStudentRowIndex` 등)은 **학번을 전교 유일값으로
전제**하고 첫 일치 행을 잡습니다. 한 시트에 두 학년도를 담으면
**2027 학생을 고치다가 2026 졸업생 기록을 덮어씁니다.**

그래서 학년도마다 시트를 나눕니다.

```
Users_2026   Attendance_2026    ← 보관
Users_2027   Attendance_2027    ← 운영 중
BlockedDates                    ← 학년도 공용 (날짜가 절대값이라 충돌 없음)
Sessions                        ← 학년도 공용 (행마다 학년도를 기록)
```

앱이 다루는 해는 스크립트 속성 **`ACTIVE_SCHOOL_YEAR`** 하나가 정하고,
`getSheets()`가 그에 맞는 시트를 돌려줍니다. 화면 상단에 `2026학년도`
배지가 떠서 지금 어느 해에 기록하는지 늘 보입니다.

### 운영 메뉴

| 메뉴 | 언제 |
|---|---|
| `📅 학년도 설정/확인` | 현재 학년도 확인, 다른 해로 전환 |
| `🎓 새 학년도 시작` | 매년 새 도제반을 받을 때 |
| `📦 기존 데이터를 학년도 시트로 이관 (1회)` | 학년도 분리 도입 시 한 번만 |

### 새 학년도 시작 절차

**1~2월에 하세요.** OJT가 3~12월 운영이라 그 사이에는 출결이 발생하지 않아,
학년도 경계가 데이터 경계와 정확히 일치합니다.

1. **백업** — `파일 → 사본 만들기`
2. `🎓 새 학년도 시작` → 연도 입력 → 확인
3. 교사 화면에서 **새 학생 명단 등록**

메뉴가 하는 일:

- `Users_YYYY` / `Attendance_YYYY` 생성 (헤더 포함)
- **교사 계정을 비밀번호 해시·솔트 그대로 승계** (잠금 상태는 초기화)
- 활성 학년도 전환, 모든 로그인 세션 정리
- 지난 학년도 시트는 **그대로 보존**

> **교사 계정이 0명이면 전환을 중단합니다.** 승계에 실패하면 아무도
> 로그인할 수 없기 때문에, 진행 전에 세어보고 막습니다.

> **학생 계정은 승계하지 않습니다.** 새 학년도는 새 명단입니다.

### 지난 학년도 기록 보기

앱 화면은 **활성 학년도만** 보여줍니다. 지난 해 기록은 스프레드시트에서
`Users_2026` / `Attendance_2026` 탭을 직접 엽니다.

활성 학년도가 아닌 해의 월간 레포트를 요청하면 **거부하고 어느 탭을 보면
되는지 알려줍니다.** 지금 열린 명단에 남의 해 날짜를 맞추면 전원 결석이라는
조용한 오답이 나오기 때문입니다.

### 안전장치

| 상황 | 동작 |
|---|---|
| 활성 학년도 미설정 | 모든 요청 거부 + 설정 안내 (조용히 빈 명단을 돌려주지 않음) |
| 시트 없는 해로 전환 시도 | 전환 거부 |
| 이미 있는 학년도를 또 만들려 함 | 생성 거부 (덮어쓰지 않음) |
| **지난 학년도 토큰으로 접근** | **거부** — `Sessions`의 학년도 열과 대조 |
| 학년도 전환 | 모든 세션 정리 (전원 재로그인) |

> ⚠️ **`Sessions`의 학년도 열은 보안상 필수입니다.** 학번이 재사용되므로,
> 연도 없이 검증하면 2026년 31201의 토큰이 2027년 31201(다른 사람)의
> 데이터에 그대로 통합니다.

## 시트 스키마

### `Users` — 계정

| 열 | 필드 | 설명 |
|:---:|---|---|
| A | `ID` | 학번 또는 교사 ID (기본키) |
| B | `NAME` | 이름 |
| C | `ROLE` | `학생` \| `교사` |
| D | `PW` | 솔트+페퍼 HMAC-SHA256 2000회 해시 (64자리 Hex) |
| E | `IN_TIME` | 입실 기준시간 `HH:MM` |
| F | `OUT_TIME` | 퇴실 기준시간 `HH:MM` |
| G | `FAIL` | 로그인 연속 실패 횟수 |
| H | `LOCK` | 잠금 해제 시각 (ms epoch) |
| I | `SALT` | 계정별 무작위 솔트 (비어있으면 레거시 계정) |
| J | `MUST_SETUP` | 초기 설정 강제 여부 `TRUE`/`FALSE` |
| K | `LEFT_DATE` | 퇴반일 `yyyy-MM-dd`. **비어 있으면 재학 중** |

> **`LEFT_DATE`는 '출결 대상에서 빠지는 첫 날'입니다.** `2026-09-15`이면 9/15부터
> 제외되고 9/12까지는 집계 대상입니다. 모든 판정이 **조회 날짜와 비교**하므로,
> 퇴반이 생겨도 그 이전 기간의 대시보드와 월간 레포트는 바뀌지 않습니다.
>
> 중도에 그만둔 학생은 **삭제하지 말고 퇴반 처리**하세요. 삭제하면 Users 행이
> 사라지는데 대시보드와 레포트가 Users 기준으로 명단을 만들기 때문에, 그 학생이
> 재학 중 남긴 출결까지 화면에서 함께 빠집니다(지난 달 출석부가 소급해 바뀝니다).

### `Attendance` — 출결 로그 (append-only)

| 열 | 필드 | 예시 |
|:---:|---|---|
| A | `TIME` | `08:55:12` |
| B | `DATE` | `2026-08-19` |
| C | `DAY` | `수` |
| D | `ID` | `31201` |
| E | `NAME` | `홍길동` |
| F | `TYPE` | `입실` \| `퇴실` |
| G | `STD_TIME` | `09:00` (기록 시점의 기준시간 스냅샷) |
| H | `STATUS` | `정상` \| `지각` \| `조퇴` \| `공결` |

### `BlockedDates` — 차단일 (자동 생성)

| 열 | 필드 | 예시 |
|:---:|---|---|
| A | `DATE` | `2026-05-01` |
| B | `REASON` | `근로자의 날` |
| C | `BLOCKED` | `TRUE` / `FALSE` |

### `Sessions` — 세션 토큰 (자동 생성)

| 열 | 필드 | 설명 |
|:---:|---|---|
| A | `TOKEN` | 발급된 UUID |
| B | `ID` | 사용자 ID |
| C | `ROLE` | **서버가 발급 시점에 기록한 역할** (권한 검증의 기준) |
| D | `EXPIRES` | 만료 시각 (ms epoch) |
| E | `YEAR` | **발급 시점의 학년도.** 활성 학년도와 다르면 거부합니다 — 학번이 재사용되므로 이 검사가 없으면 지난 해 토큰이 같은 학번의 다른 사람에게 통합니다 |

### Script Properties

| 키 | 용도 |
|---|---|
| `PW_PEPPER` | 비밀번호 페퍼. 최초 요청 시 자동 생성되며 **시트에 저장되지 않습니다.** |
| `ACTIVE_SCHOOL_YEAR` | **앱이 다루는 학년도.** 없으면 모든 요청이 거부됩니다. `📅 학년도 설정/확인` 메뉴로 관리합니다 |
| `usersSchemaReady_v3_YYYY` | Users 시트 G~K열 준비 완료 플래그. **학년도별로 분리**되어 있습니다 — 하나로 두면 새 학년도 시트에 열이 생기지 않습니다. 열을 추가하면 `v3` 버전을 올리세요 |
| `sessionsSchemaReady_v2` | Sessions 시트 학년도(E) 열 준비 완료 플래그 |
| `ALERT_EMAIL` | 일일 마감 알림 수신 주소(쉼표 구분). 비어 있으면 스크립트 소유자에게 발송. `📧 알림 받을 메일 주소 설정` 메뉴로 관리합니다 |
| `lastDailyAlertDate` | 알림을 마지막으로 보낸 날짜. 같은 날 트리거가 두 번 돌아도 중복 발송하지 않게 합니다 |
| `lastSessionCleanupDate` / `lastHiddenDate` | 세션 정리·지난 행 숨김을 하루 한 번만 수행하기 위한 날짜 기록 |

> **주의**: `PW_PEPPER`를 분실하거나 변경하면 **모든 계정의 비밀번호 검증이 실패합니다.**
> 스크립트를 다른 프로젝트로 이전할 때는 이 값도 함께 옮겨야 합니다.

## API

모든 요청은 `/exec`에 대한 단일 `POST`이며, 본문은 `{ action, ... }` 형태의 JSON입니다
(`code.gs` 의 `doPost`).

> **`Content-Type: application/json` 헤더를 추가하지 마세요.** GAS 웹앱은 CORS preflight(`OPTIONS`)에
> 응답하지 않습니다. 현재 `index.html` 의 `callAPI`는 헤더를 생략해
> `text/plain`으로 전송되며, 이 덕분에 preflight 없이 동작합니다.

응답은 항상 `{ success: boolean, msg?: string, ... }` 형태입니다.

**요청 빈도 제한**이 세션 검증보다 앞에서 걸립니다(`exceedsRateLimit`).
60초 고정 창 기준이며 한도는 정상 사용의 몇 배로 잡혀 있습니다 —
`login` 10회, `recordAttendance` 10회, 그 외 60회(모두 id 기준).
초과 시 `요청이 너무 잦습니다...` 메시지가 반환됩니다. 한도를 조이면
`tests.gs`의 `rateLimit (정상 사용 허용)` 테스트가 먼저 깨지도록 해두었습니다.

### 인증 불필요

| action | 파라미터 | 설명 |
|---|---|---|
| `getConfig` | — | 실습요일·공휴일·지각기준 등 업무 규칙 수신 |
| `login` | `id`, `pw` | 로그인. 성공 시 `token` 발급 |
| `checkTodayBlocked` | — | 오늘이 차단일인지 확인 |
| `logout` | `token` | 세션 토큰 폐기 |

### 본인 확인 필요 (`token` + `id` 일치)

| action | 파라미터 |
|---|---|
| `initialSetup` | `pw`, `inTime`, `outTime` |
| `changePw` | `currentPw`, `newPw` |
| `recordAttendance` | `type` (`입실`\|`퇴실`) |
| `getStudentStatus` | — |
| `getMyAttendance` | `year`, `month` — 본인 월간 출결. [내 출결](#내-출결-학생-본인-월간-조회) 참조 |

### 교사 권한 필요 (세션의 `ROLE`이 `교사`)

| action | 파라미터 |
|---|---|
| `getAdminData` | `date` |

## 내 출결 (학생 본인 월간 조회)

학생 화면의 접이식 **`📅 내 출결`** 카드입니다. 본인의 이번 달 출석률과
날짜별 기록을 직접 확인합니다. 도제반은 출석률이 수료 요건에 걸리므로,
학생이 스스로 보면 사후 분쟁과 문의가 줄어듭니다.

- 기본은 **접힘**입니다. 이 화면의 본래 목적인 입·퇴실 버튼을 밀어내지 않기 위해서입니다.
  접힌 머리글에는 이번 달 출석률만 한 줄로 보여줍니다.
- **처음 펼칠 때 한 번만** 서버를 부릅니다. 접었다 펴는 것만으로 매번 요청하면
  학생 수 × 반복 클릭이 그대로 GAS 할당량이 됩니다.
- 입·퇴실을 기록하면 펼쳐둔 목록도 함께 갱신됩니다.
- 월 이동은 **올해 1월 ~ 이번 달**까지입니다. 미래는 집계 대상이 아닙니다.

**출석률 = (집계 대상 실습일 − 결석일) ÷ 집계 대상 실습일**

지각·조퇴·공결은 **출석으로 칩니다**(결석만 깎습니다).
90% 이상 초록 / 80%대 주황 / 그 아래 빨강으로 표시합니다.

집계 대상 실습일은 월간 레포트와 **같은 함수**(`getScheduledReportDates`)가 뽑고,
퇴반 이후의 날은 분모에서 빠집니다(`isEnrolledOn`). 학생 화면과 교사 출석부의
숫자가 다르면 그 자체가 분쟁거리이므로, `tests.gs`에 두 집계를 맞대어 보는
테스트(`test_myAttendance_matchesMonthlyReport`)를 두었습니다.

> 1~2월은 오류가 아니라 '실습일 0일'인 달로 취급해 안내문을 보여줍니다.

### 학생이 중도에 그만두면

`학생 관리` 탭에서 그 학생 행의 **`[📤 퇴반]`** 을 누르고 날짜를 고릅니다
(기본값 오늘, 그 날짜부터 출결 대상에서 빠집니다).

- 계정과 출결 기록은 그대로 남고, **퇴반 이전 기간의 대시보드·출석부는 바뀌지 않습니다.**
- 퇴반 학생은 목록에서 기본 숨김입니다. `퇴반 학생 N명 보기` 토글로 펼치면
  **바이올렛 점선 테두리**가 둘린 행으로 표시되고, `[🔄 복구]` 로 되돌릴 수 있습니다.
- 월간 레포트에는 이름 아래 `퇴반 09-15` 가 붙고, 퇴반 이후 실습일은 결석이 아니라
  회색 `–` 로 표시됩니다. 그 달 전체가 퇴반 이후면 명단에서 빠집니다.
- 퇴반 처리하면 그 학생의 로그인이 차단되고 기존 세션도 즉시 끊깁니다.

> **`[🗑️ 삭제]` 는 잘못 등록한 계정을 지울 때만 쓰세요.** 중도 퇴반에 쓰면
> 재학 중 남긴 출결까지 대시보드·레포트에서 함께 빠집니다.

## 보안 설계

- **비밀번호**: 계정별 무작위 솔트(시트 I열) + 스크립트 속성의 페퍼로 HMAC-SHA256을 2000회
  반복합니다(`hashPassword`). 페퍼가 시트 밖에 있으므로 시트 열람 권한만으로는
  해시를 역산할 수 없습니다.
- **레거시 자동 승급**: 평문 또는 단일 SHA-256으로 저장된 계정도 로그인은 되며, 성공 즉시
  신규 체계로 재저장됩니다(`matchStoredPassword`).
- **브루트포스 방어**: 5회 실패 시 5분 잠금. 실패 응답은 원인을 구분하지 않는 단일 메시지이며,
  200~500ms 랜덤 지연으로 타이밍 공격을 막습니다(`checkLogin`).
- **권한 위조 방지**: 교사 전용 API는 클라이언트가 보낸 role이 아니라 `Sessions` 시트에
  **서버가 기록한** role로 검증합니다(`verifySessionToken`).
- **로그인 유지**: 세션은 `localStorage`에 저장되어 브라우저를 닫아도 이어지며,
  **[로그아웃]을 누를 때까지 유지됩니다.** 무활동 자동 로그아웃은 없습니다.
  > ⚠️ **공용 PC에서는 반드시 [로그아웃]을 눌러야 합니다.** 누르지 않고 자리를 뜨면
  > 다음 사용자가 그 계정으로 출결을 기록할 수 있습니다(대리 출석).
  > 짧은 만료로 되돌리려면 `SESSION_TTL_MS`를 줄이세요 — 다만 프론트에는 만료를
  > 미리 알려주는 장치가 없어서, 사용 도중에 튕기게 됩니다.
- **ID 열거 방지**: 학번 존재 여부만 확인하는 엔드포인트는 의도적으로 제거되어 있습니다.
- **동시성**: 모든 읽기→수정 작업이 `LockService.getScriptLock()`을 경유합니다.
  로그인은 솔트 해싱을 락 **밖에서** 선계산해 락 점유 시간을 줄입니다(`checkLogin`).
- **XSS**: 프론트 `esc()` / 백엔드 `escapeHtml()` 이중 이스케이프.

## 개발 시 참고

- **빌드 과정이 없습니다.** `index.html`을 직접 편집하고 저장하면 끝입니다.
- **단일 파일 구조는 의도된 선택입니다.** HTML·CSS·JS를 별도 파일로 쪼개지 마세요.
  배포가 "`index.html` 하나를 올린다"로 끝나는 것이 이 프로젝트의 장점입니다.
  구획은 기존 `// ═══` / `// ───` 배너 주석 규칙을 따르고, 코드를 가리킬 때는
  줄번호 대신 함수명을 쓰세요.
- **프론트와 백엔드에 같은 규칙을 중복 정의하지 마세요.** 새 업무 규칙은 `code.gs` 상수에
  추가하고 `buildClientConfig()`로 내려보냅니다.
- **`alert()`/`confirm()`/`prompt()` 대신 `showAlert()`/`showConfirm()`/`showPrompt()`를
  쓰세요.** 셋 다 Promise를 반환합니다 — `await showConfirm("삭제할까요?")`.
  `showPrompt(message, { label, inputType, value })`는 확인 시 입력값,
  **취소 시 `null`** 을 돌려줍니다(빈 문자열도 유효한 값이라 반드시 `null`로 구분).
  `inputType: "date"`를 주면 브라우저 기본 날짜 선택기가 뜹니다.
  세션이 끊기는 경로에서는 `logout()`을 **먼저** 부르고 안내를 띄우세요. 모달은 사용자가
  확인을 누를 때까지 열려 있어서, 순서를 반대로 하면 그동안 로그인 상태가 유지됩니다.
- **날짜·시각 문자열은 `formatKST()`로 만드세요.** `nowKST()`는 요일·시각 '필드' 접근
  전용입니다. `Utilities.formatDate(nowKST(), 'GMT+9', ...)`처럼 쓰면 이중 변환이 되어
  스크립트 시간대가 `Asia/Seoul`이 아닐 때 날짜가 어긋납니다.
- **메일을 보내는 코드는 `doPost` 라우터에 올리지 마세요.** `/exec`는 누구나 호출할 수
  있는 공개 엔드포인트라 스팸 통로가 됩니다. 알림은 시간 기반 트리거와 시트 메뉴에서만
  호출합니다(`dailyAttendanceAlert` / `manualSendDailyAlert`).
- **집계와 발송을 분리해 두었습니다.** `buildDailyAlertSummary()`는 시트만 읽고
  `{send, reason, absent, late, noExit, …}`를 돌려주고, `sendDailyAttendanceAlert()`가
  그 결과로 메일을 보냅니다. 덕분에 집계 로직은 메일을 실제로 보내지 않고 테스트됩니다.
- **테스트**: Apps Script 편집기에서 `runAllTests`를 실행하면 `tests.gs`의 테스트
  **53건**이 돌고 [실행 로그]에 결과가 나옵니다. 실제 스프레드시트에 접근하지 않으므로
  운영 데이터에 영향이 없습니다. 새 테스트는 `TEST_CASES` 배열에 한 줄 추가하면 됩니다.
  `benchmarkPasswordHash()`로는 해시 소요시간을 측정할 수 있습니다.
  알림 테스트는 `mockSheet_()` / `mockUsers_()` / `mockAttendance_()`로 시트를 흉내 냅니다 —
  2차원 배열을 감싼 평범한 객체라 `SpreadsheetApp` 없이 돌아갑니다.
  **메일 발송 자체는 테스트하지 않습니다**(실제로 메일이 날아갑니다).
- **학년도 시트를 늘리거나 열을 바꿀 때는 `getSheets()` 한 곳만 고치세요.**
  시트 이름이 코드에 박힌 곳은 `getSheets` / `ensureBlockedDatesSheet` /
  `ensureSessionsSheet` 세 곳뿐이고, 나머지 함수는 전부 시트 객체를 인자로 받습니다.
  **`Users` 스키마에 열을 추가하면 `usersSchemaProp()`의 `v3` 버전을 올리세요** —
  플래그가 켜져 있으면 `ensureUserSheetColumns()`가 통째로 건너뜁니다.

### 파일 편집 시 인코딩 주의

모든 파일은 **BOM 없는 UTF-8**입니다. Windows PowerShell의 `Get-Content` / `Set-Content`로
일괄 치환하면 UTF-8을 CP949로 읽어 **한글이 전부 깨집니다.** 편집기나
`[System.IO.File]::ReadAllText($path, [System.Text.Encoding]::UTF8)`를 쓰세요.
