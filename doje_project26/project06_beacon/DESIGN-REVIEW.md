### 알림 카드 — 버튼 안의 버튼

헤더(`.alert-head`)에 `role="button"` + `tabindex="0"`이 달려 있고, 그 안에
시간대 필터 `<button>` 4개가 들어 있었습니다. 버튼 안에 버튼이 중첩된 구조입니다.

스크린 리더는 버튼 내부를 **하나의 이름으로 눌러 읽기 때문에**, 헤더의 접근성
이름이 `"입실 미입력 09:00 3 09:30 1 10:00 7 13:00 2 10명"`처럼 뭉개지고
개별 칩이 컨트롤로 노출되지 않습니다.

**수정**: 헤더에서 `role`·`tabindex`·`aria-expanded`를 떼고(마우스 클릭 영역으로만
남김), 이미 있던 화살표 아이콘 `.alert-toggle-icon`을 진짜 `<button type="button">`으로
바꿔 `aria-expanded`·`aria-controls`·`aria-label`을 옮겼습니다.

- 마우스로 헤더 아무 곳이나 눌러 펼치는 동작은 그대로입니다.
- 키보드·보조기기 사용자는 라벨이 붙은 토글 버튼과 개별 칩 버튼을 각각 얻습니다.
- 확인 결과 **버튼 안에 중첩된 인터랙티브 요소 0개**(이전 4개).

### 통계 타일 — 색이 하던 일을 바꿨습니다

예전에는 네 타일이 각각 초록·파랑·빨강·주황 색면이었고 숫자까지 그 색으로
칠했습니다. 두 가지 문제가 있었습니다.

1. **좋은 상태가 경고처럼 보였습니다.** `지각 0명`·`조퇴 0명`이 빨강·주황으로
   칠해져서, 아무 문제 없는 날에도 눈이 그쪽으로 먼저 갔습니다.
   색이 **상태**가 아니라 **분류**를 나타내고 있었던 탓입니다.
2. **숫자가 묻혔습니다.** 네 칸 모두 큰 색면이라 정작 "몇 명인지"가 배경에
   섞였습니다.

그래서 **면을 흰색으로 비우고 색은 작은 아이콘 칩만 쥐게** 했습니다.
값은 본문 잉크색(`--heading`)으로 올리고 크기를 19px → 24px로 키웠습니다.
`지각`·`조퇴`는 **0명이면 가라앉고 1명 이상일 때만 색이 올라옵니다**
(`.is-clear` / `.is-alert`). 이제 시선이 실제 문제로 갑니다.

부수적으로 고친 것 둘:

- `.stat-val`의 `font-variant-numeric: tabular-nums` 제거 — 모든 자리를 `0` 폭으로
  맞추는 설정이라 큰 글씨에서 숫자가 헐거워 보입니다. 세로로 줄을 맞춰야 하는
  표(`.s-id`, `.time-range-badge`)에만 남겼습니다.
- `21명(완료)`처럼 숫자에 붙던 문자열을 `전원 완료` 배지로 떼어냈습니다.
- 좁은 화면에서 `.stat-ico`를 `display: none` 하던 것을 되돌렸습니다.
  아이콘 칩이 이제 이 타일의 **유일한 색 신호**라, 숨기면 네 칸이 구분되지
  않습니다.

## 🔴 A1. 활성 탭에서 키보드 포커스 링이 사라집니다

전역 규칙이 포커스 링을 담당합니다.

```css
button:focus-visible, a:focus-visible,
input:focus-visible, select:focus-visible {
  outline: none;
  box-shadow: var(--ring);
}
```

선택자 우선순위가 **(0,1,1)** 입니다. 그런데 `.tab-btn.active` 처럼 클래스 2개를
쓴 규칙은 **(0,2,0)** 이라 이쪽이 이깁니다. 두 규칙이 같은 `box-shadow` 속성을
다투므로, 활성 탭에서는 포커스 링이 그려지지 않습니다.

해당하는 **포커스 가능한** 규칙 6종입니다.

| 선택자 | 화면 |
|---|---|
| `.tab-btn.active` (+ `.tab-nav-*` 4종) | 교사 메인 4탭 |
| `.dash-subtab-btn.active` | 대시보드 확인필요/기록상세 |
| `.auth-role-tab.active` | 학생/교사 로그인 탭 |
| `.bl-tab.active` | 차단 목록 월별 탭 |
| `.alert-filter-tab.active` | 시간대 필터 칩 |
| `.page-btn.active` | 페이지네이션 |

**하필 지금 선택된 탭에서만 안 보입니다.** 키보드로 이동하면 대개 그 위에
서 있게 되므로, 실제로는 "탭 영역에서 내가 어디 있는지 알 수 없는" 상태가 됩니다.

> 참고로 `.btn-primary` · `.btn-in` · `.nav-btn` 처럼 **클래스 1개**인 규칙은
> (0,1,0) 이라 포커스 링이 정상적으로 이깁니다. 문제는 `.active` 조합뿐입니다.

**수정 방향** — 링을 `box-shadow` 대신 `outline`으로 옮기면 속성 충돌 자체가
없어져서 우선순위 싸움이 사라집니다. 그림자를 쓰는 컴포넌트와도 공존합니다.

```css
button:focus-visible, a:focus-visible,
input:focus-visible, select:focus-visible {
  outline: 3px solid rgba(59, 130, 246, 0.55);
  outline-offset: 2px;
}
```

`outline`은 이제 `border-radius`를 따라가므로 모양도 깨지지 않습니다.

## 🔴 A2. 삭제 버튼이 손가락으로 누르기에 작습니다

```css
.student-action-btn { min-height: unset; padding: 5px 8px; font-size: 11px; }
/* 모바일 */
.student-action-btn { padding: 4px 6px; font-size: 10.5px; }
.student-action-group { gap: 3px; }
```

높이가 **약 26px, 모바일에서 약 23px**, 버튼 간격은 **3px**입니다.
일반 권장치(iOS 44pt / Android 48dp / WCAG 2.5.5 44px)의 절반입니다.

이 세 버튼이 `[✏️ 수정]` · `[🔑 PW]` · `[🗑️ 삭제]` 입니다.
**비밀번호 초기화와 계정 삭제는 되돌리기 어려운 동작인데**, 23px짜리 버튼이
3px 간격으로 붙어 있으면 오탭이 납니다.

원인은 명확합니다. PRD §4.4가 "좁은 화면에서도 세로 줄바꿈 없이 가로 1줄
(`flex-wrap: nowrap`)"을 요구했고, 구현은 **버튼을 줄여서** 그 요구를 맞췄습니다.
`min-height: unset`이 그 흔적입니다 — 기본 높이를 일부러 꺼버린 것입니다.

**수정 방향** — 가로 1줄을 지키면서 크기를 회복하는 길이 있습니다.

- 모바일에서 아이콘만 남기고(텍스트 숨김) 정사각 40×40px 버튼 3개로.
  40×3 + gap 8×2 = 136px 이라 360px 화면에도 충분히 들어갑니다.
- 또는 `수정`만 노출하고 `PW`·`삭제`는 `⋯` 오버플로 메뉴로 접기.
  파괴적 동작을 한 단계 뒤로 보내는 효과도 같이 얻습니다.

`.page-btn`도 34×34px이라 같이 40px 이상으로 올리는 것이 좋습니다.
(`.nav-btn`은 44px로 이미 올바릅니다.)

## 🟠 B2. 타이포그래피에 척도가 없습니다

`font-size`가 **22종**입니다.

```
9.5 · 10 · 10.5 · 11 · 11.5 · 12 · 12.5 · 13 · 13.5 · 14 · 14.5
15 · 15.5 · 16 · 16.5 · 17 · 18 · 19 · 20 · 22 · 30 (px)
```

0.5px 단위로 거의 연속입니다. 이건 척도가 아니라 **그때그때 맞춘 값**입니다.
`:root`에 색·모서리·그림자 토큰은 있는데 **타이포 토큰만 없습니다.**

실제로 `13px`(15회) · `12.5px`(10회) · `13.5px`(6회)가 나란히 쓰입니다.
셋을 구분해서 얻는 것은 없고, 화면마다 미세하게 다른 크기가 섞입니다.

**수정 방향** — 6~7단 척도로 수렴시키고 토큰화합니다.

```css
--fs-xs: 11px;   /* 보조 라벨 (하한) */
--fs-sm: 12px;   /* 표 안 보조 정보 */
--fs-md: 13px;   /* 목록 기본 */
--fs-base: 15px; /* 본문 */
--fs-lg: 18px;
--fs-xl: 22px;
--fs-2xl: 30px;
```

### 11px 이하 글자가 21곳

`9.5px` 2곳, `10px` 2곳, `10.5px` 5곳, `11px` 12곳.
교사가 명단을 훑는 화면에서 10px 한글은 작습니다. **11px를 하한으로 잡고**
그 아래는 크기를 줄이는 대신 색(`--text-muted`)으로 위계를 주는 편이 낫습니다.

### 거의 전부가 굵은 글씨입니다

| 굵기 | 선언 수 |
|---:|---:|
| 800 | 36 |
| 700 | 33 |
| 600 | 12 |
| 500 | 1 |

명시된 굵기의 **85%가 700 이상**입니다. 전부 강조하면 강조가 사라집니다.
숫자·상태 배지처럼 정말 눈에 걸려야 하는 것만 800으로 남기고, 나머지 라벨은
600으로 낮추면 오히려 중요한 값이 더 잘 보입니다.

것으로 보입니다. 화면 폭을 줄여가며 확인할 때 어디서 무엇이 바뀌는지 예측하기
어렵고, 새 컴포넌트를 넣을 때 어느 중단점에 맞춰야 할지 판단이 안 섭니다.

3~4개로 수렴을 권합니다 — 예: `380` (초소형) · `480` (모바일) · `640` (태블릿) ·
`900` (데스크톱).

## 🟡 C4. `theme-color`가 화면과 반대입니다

```html
<meta name="theme-color" content="#0b1120" />   <!-- 거의 검정 -->
```

그런데 앱은 밝은 테마 전용입니다 — `prefers-color-scheme` 규칙이 **0건**이고
배경은 `--bg: #e7ecf3`입니다.

모바일 크롬에서 **주소창만 검게, 페이지는 밝게** 나옵니다. 다크 테마를 지원할
계획이 아니라면 배경색과 맞추는 게 자연스럽습니다.

```html
<meta name="theme-color" content="#e7ecf3" />
```

## ✅ 잘 되어 있는 부분

지적만 늘어놓았지만, 이 규모의 프로젝트에서 보기 드물게 챙겨진 것들이 있습니다.

- **`prefers-reduced-motion: reduce` 처리가 있습니다.** 애니메이션을 많이 쓰는
  UI인데 이걸 챙긴 건 드뭅니다.
- **`@media (hover: none)` 분기가 있습니다.** 터치 기기에서 hover 상태가 눌러붙는
  문제를 의식한 것입니다.
- **`:focus-visible`을 씁니다.** `:focus`가 아니라서 마우스 클릭 시 불필요한 링이
  뜨지 않습니다. A1만 고치면 포커스 처리는 제대로 동작합니다.
- **폰트 폴백이 튼튼합니다.** Pretendard 실패 시 OS별 한글 폰트로 자연히 내려가도록
  `Apple SD Gothic Neo` / `맑은 고딕` / `Noto Sans KR`까지 깔아뒀습니다.
  CDN 차단 환경을 실제로 고려한 흔적입니다.
- **토큰 주석이 이유를 씁니다.** "카드가 흰색이므로 배경은 한 톤 더 눌러야
  카드가 떠 보인다" 같은 설명은 값만 적힌 토큰보다 훨씬 유용합니다.
